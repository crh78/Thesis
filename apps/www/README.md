# @thesis/www

The public Thesis app (phase 1, web first): a mobile-first, installable web app that looks and works like the iOS app, so nobody needs the native one. Live at **https://yourthesis.xyz** on Vercel (project `thesis`, root directory `apps/www`). `/t/<take-id>` is a take's page with a link preview, and anyone can trade or fade it from the browser on the shared fork with play money.

## What's in it

- **Sign-in:** X, Google or email (Privy, headless: our own buttons), the same Privy app as iOS, so the same account reaches the same embedded wallet and profile. X sign-in is behind `NEXT_PUBLIC_X_LOGIN=on` (`lib/flags.ts`; set in Vercel), and comes first, so a reply to the X bot maps to the replier's account. Signed-out visitors get the welcome screen; take, called-it (`/c/<id>`), draft (`/d/<id>`) and profile (`/u/<handle>`) pages stay public, and Trade opens sign-in in a sheet (`components/SignIn.tsx`).
- **Onboarding** (`components/Onboarding.tsx`, `lib/session.tsx`): the iOS steps (profile with live handle check, photo, where you live, people to follow), drawn over any page until done. Non-X sign-ins are asked once to connect X.
- **Screens, each mirroring iOS:** Home (`components/Feed.tsx`: For you / Following, rows with return, sparkline, allocation bar, Trade / Fade via `?side=`; the X bot's drafts for you at the top, `components/XDrafts.tsx`; auto-copied takes never show here), Scores (own P&L, made for backers, faders; by $ or %, highest or lowest first; your line pinned), Search (Takes, People, Assets; topic chips and trending when empty), asset pages (chart 1D–1Y, takes holding it), comments (`?comments=1`), notifications, the profile drawer (`components/Drawer.tsx`, with `/saved`, `/people/following|followers`, `/settings`), and Copy from X (`app/(tabs)/x`, through the `source` function's X routes; Copy on a call opens the composer drafted; tapping an account shows its Auto-copy bar).
- **New take** (`components/Composer.tsx`, `lib/compose.ts`): write → risk (no horizon: a take runs until its author sells their buy-in, a year at most) → the take builder's basket (`/api/take-builder`) → edit (risk switch, "Change something…", weights, add/remove) → buy in and post. Posting is the social function's `POST takes` with `await_chain`, then the fork API's publish; the screen waits for the chain to make it live, else Retry or Discard (`components/PostingRecovery.tsx`). Fade shows on a take only when a leg can be faded (the builder's `canShort`).
- **Me** (`app/(tabs)/me`): both scores, the portfolio chart, cash with Add cash ("$X of $1,000 left to add", from `depositLeftUsd`, which follows a wallet's own cap; no Withdraw), creator fees with Claim all, open positions (swipe one left, or tap its red arrow, to sell all of it: `components/SellAll.tsx`), stopped trades, your takes (including posting ones) and badges. After a trade it re-checks the portfolio every 5 s for two minutes.
- **Trading by text** (`app/(tabs)/limits`, from Settings): per-trade and daily limits, allowed once by adding Thesis's Privy session signer to the wallet (`useSigners`), changed or turned off any time; `/limits?link=<token>` connects the iMessage number that asked. Through `/api/agent/*` (only `grant`, `links/<token>` and `copies…`).
- **Copy trading** (`app/(tabs)/copy`, in the drawer; `lib/copies.ts`): everyone you copy (X accounts and Thesis traders) with each one's Auto-copy switch, $ per call and daily cap, and your recent auto-copies (copied, pending or skipped, and why). Profiles have a **Copy** button next to Follow (`components/CopyButton.tsx`). Needs trading by text. Through `/api/agent/copies…`.
- **Trade from X and iMessage** opt-in (`components/AppPrompts.tsx`): once per account after onboarding, when trading by text is off: "Set my limits" (opens `/limits`) or "Not now".
- **Takes from X** show a "Take from X ↗" tag on the feed card and the take page, linking to the post (`xSource` in `lib/data.ts`).
- **Pictures for the X bot**, drawn from the app's data with `next/og`: `/d/<id>/basket.png` (a draft's claim, a donut of its picks with logos and weights) and `/u/<handle>/score.png` (a person's two scores, calls, P&L line and best take).
- **Install and push** (`components/AppPrompts.tsx`, `lib/push.ts`, `public/sw.js`): an install prompt once per account on phones; once running from the home screen, a one-time push prompt. New notifications fire a trigger (`*_web_push.sql`) that calls `functions/web-push`. The VAPID public key is in `lib/push.ts`; the private key is a function secret.
- **Shell:** the iOS tab bar, palette (system light/dark) and Geist fonts. No play-money or fork labels beyond one quiet line on the welcome screen. On desktop, the phone column centered with a QR code for the current page (`components/DesktopPanel.tsx`). `app/manifest.ts` and `app/apple-icon.png` for home-screen installs; `opengraph-image.tsx` draws link previews.

## Trading

Like iOS: the fork API builds, the Privy wallet signs (`signTransaction`, never sends; all of a build's transactions at once), the API sends. Back, fade (Phoenix shorts and "No" on prediction legs; card legs left out), sell, Phoenix cash-out, add play money. The routes and their errors are in [`scripts/fork/README.md`](../../scripts/fork/README.md#fork-api-the-apps-fork-mode).

- **Buy | Sell tabs** (`components/TradeDock.tsx`): Sell sells part or all of your holding on that side, by % or $ (`POST /takes/:id/sell`), and says why when an amount would leave less than $10. At All on your own buy-in it warns that the sale closes the take.
- **Fast trades** (`lib/trade.ts`): the sheets build before the tap (`prebuild: true`): when the sheet opens at its amount, at once on a chip, 500 ms after typing stops. Builds are kept per amount and refreshed (`POST /builds/:id/refresh`) with under 15 s left while the sheet is visible, until it's been untouched for 3 minutes; the tap signs a fresh one or builds then. Early builds go on only once one answered `prebuilt: true`; otherwise the page makes one early build and the tap builds. A build is used for at most 50 s from when it was asked for, whatever its `expiresAt` (a phone's clock can be behind).
- **Accept, then confirm:** `/submit` goes with `until: "accepted"` and the tap's `timings` (ms since the tap: `built`, `sign<i>`, `signed`, `submit`; after "shown" and how it ended, the same submit is sent once more so the API logs those too). "You're in · Confirming on-chain…" shows as soon as the fork accepts it; `GET /submissions/:id` watches it to the end (the build id is kept in sessionStorage and checked before the next build, also after a reload). A trade that doesn't confirm says "That trade didn't go through. Nothing left your balance." (a sale: "You still hold the position."), with Try again. An older fork API (no `status: "pending"`) gets the old wait-for-confirmation answer.
- **Stopped trades** (`components/StoppedTrade.tsx`): a split trade that stops partway (`trade_incomplete`) is finished at once with its one retry, signed without asking, and a submit refused with `requote: true` (nothing sent) is built again and signed once more. Only if that fails does the sheet offer "Finish the trade" (`POST /wallets/:w/retry`, while the retry is left), then "Swap the leftover back to cash" (`POST /wallets/:w/sweep`, then the Phoenix cash-out if it says so). Me lists stopped trades (`GET /wallets/:w/incomplete`) with the same actions, so they can be sorted out after a reload or on another device. A sale that stops partway is finished by selling that position again (the fork API builds what didn't land).

## Fork calls

`lib/fork.ts`. With `NEXT_PUBLIC_FORK_API_URL` set (production), the browser calls the fork API directly (it allows this site's origin through `FORK_API_CORS_ORIGINS`), so fork reads cost no Vercel function calls; without it, they go through `/api/fork/*`.

- Every call but `/submit` carries the signed-in person's Privy token as `Authorization: Bearer …` (money calls check it; reads count per Privy user instead of per IP). `/submit` needs none, so it goes as text/plain with no token: a CORS simple request with no preflight. Creator fees add `x-thesis-wallet-auth`.
- A network failure reads "Can't reach Thesis right now"; a 429 says how long to wait from `Retry-After`; a 401 or `wrong_wallet` shows "Sign in again".
- **Server routes:** `/api/fork/*` proxies the fork API for a deploy without `NEXT_PUBLIC_FORK_API_URL`; the server adds `x-thesis-proxy-key` (`FORK_API_PROXY_KEY`) and `x-thesis-client-ip`, never the browser. Server renders (take, profile and link-preview pages) read the fork API at `FORK_API_URL` with the service key, so they aren't rate-limited as one Vercel IP. `/api/session`, `/api/social/*`, `/api/source/*`, `/api/assets/*`, `/api/push/*`, `/api/agent/*` and `/api/take-builder` proxy those edge functions. `/actions.json` and `/api/actions/*` go to the closed Blink only when `FORK_BLINK_URL` is set.

## Running and deploying

```sh
cp apps/www/.env.example apps/www/.env.local   # then fill in the values (gitignored)
pnpm --filter @thesis/www dev                  # http://localhost:3100 (Privy allows localhost)
```

Vercel builds production from `main` only (`vercel.json`): merging a PR deploys it, and PR branches get no preview builds (the Hobby plan allows 100 deploys a day). After changing a setting in Vercel, redeploy production so the build picks it up.

Privy dashboard: X and Google on under Authentication → Socials (our own X OAuth client before going public; Privy's default keys are for development), and the web origins (`http://localhost:3100`, `https://yourthesis.xyz`) in the allowed domains.

## Settings

`.env.example` lists them; locally in `apps/www/.env.local`, in Vercel as project environment variables. None has a default, and the build succeeds without them: a missing one fails the request that needs it with an error naming it.

- **Required, client** (inlined at build time, so set them before building): `NEXT_PUBLIC_PRIVY_APP_ID` (the same Privy app as iOS), `NEXT_PUBLIC_SUPABASE_URL` (`https://<project-ref>.supabase.co`), `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- **Required, server only:** `FORK_API_URL` (`https://<fork-host>`); `FORK_API_PROXY_KEY` (the secret the fork API shares with the proxy, the same value as the VM's); `FORK_API_SERVICE_KEY` (the secret of a `web=<secret>` entry in the VM's `FORK_API_SERVICE_KEYS`; server only, since a service key may act for any wallet).
- **Optional:** `NEXT_PUBLIC_FORK_API_URL` (client; the same host as `FORK_API_URL`; set in production): the browser calls the fork API directly. Add this site's origins to the VM's `FORK_API_CORS_ORIGINS` first, then set it and redeploy; unset it to go back to the proxy. `NEXT_PUBLIC_X_LOGIN` (`on` for X sign-in). `NEXT_PUBLIC_X_BOT_HANDLE` (the X bot the screens name; defaults to `yourthesisxyz` in `lib/flags.ts`). `NEXT_PUBLIC_SITE_URL` (defaults to Vercel's production URL, the custom domain). `NEXT_PUBLIC_VAPID_PUBLIC_KEY` (defaults to the key in `lib/push.ts`). `FORK_BLINK_URL` (server; the closed Blink at `https://<fork-host>:8443`).
