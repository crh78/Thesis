# @thesis/agent

Chat agent brain, independent of transport: one OpenAI Responses call per inbound message (Luna), with tools for what a chat can do. Today that's `build_basket`: a take → the `source` function's `POST /source/drafts` (`THESIS_BOT_SECRET`), which runs the `take-builder` and saves the basket as a **draft take**. The answer is the draft's web page (`WEB_URL/d/<id>`), where whoever taps posts it as their take. It also trades for the sender, from their own account, within the limits they approved on the web app (`/limits`): `post_take` (a basket as their take, with a buy-in), `back_take`, `fade_take`, `sell_position` (all, a percent or dollars) and `my_positions`, through the `agent` function's bot routes (`src/trade.ts`; Privy session signer, per-trade and daily limits). Trades wait for a yes (`src/confirm.ts`): the tool sets the trade up, the bot asks "On it. Like this message or reply yes to confirm: …", and a like/love tapback or "yes" runs it with no model call. A sender who hasn't connected gets a one-time link; a trade over the limits gets the take's link to do it by hand. Each chat remembers its last few drafts and take links, so "Jake's take" resolves; trades are keyed on the message id, so a redelivery never trades twice.

Used by `apps/imessage` (the chat agent) and `apps/x` (`buildBasket` only; X has its own vetting and reply templates).

Try it without iMessage: `pnpm --filter @thesis/agent chat "AI power demand is underrated"` (add `--group` for group behaviour; `--as +1555…` trades from the account that number is connected to, for real on the fork).
